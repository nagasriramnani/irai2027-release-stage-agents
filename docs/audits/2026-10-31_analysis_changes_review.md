## semantics

- **[minor]** chance_correct counts a credited answer as evidenced when ANY served source's recompute() returns it, whatever that source measures. For comparison items recompute() only needs the two entity keys, so a source on a different metric for the same two entities always 'yields' one of the two names. A guessed side of a comparison, which the docstring gives as the example of chance-correct, is then counted as evidenced about half the time, whenever the agent happened to read such a source. The scorer avoids this for value_src with an auth_titles filter (score.py:128-129); evidence_flags has no such filter. This is latent: in the current Qwen dev outputs every evidenced correct run includes a version of the answering dataset, so HFiveChance=5, n_evidenced=304 and the 'chance' column are right. It will undercount in the Llama run and in confirmatory runs, where unrelated sources give gold for 107 categorical and 58 numeric item x stage pairs (dev: 10, all categorical). (where: harness/analyze.py:117-118 (evidence_flags, chance_correct)) 
  - fix: Count only sources relevant to the item as evidence. That means versions of the answering dataset (title in the titles of gold_for(it, env.cfg)[2], as score.py:128 does) plus the item's own confounders (confounders stale/distractor/prohibited and the override's stale_extra), so a forbidden or stale record of the same metric still counts as received evidence. For example: rel = {s for s in served if env.sources[s]['title'] in auth_titles or s in own_ids}; chance_correct = correct and not any(value_match(ans, recompute(it, env.sources[s]['values']), it) for s in rel). Add a one-line assert with the OPE-COMP-DIST-02/SRC-0007 case to run.py's self-check.

## pipeline

- **[major]** The Llama-style analysis compares one Llama repetition (rep 0) with reference-agent runs from reps 0 and 1. The fault-free stratum, the DiD and the \LlamaIdeal* macros therefore depend on a seed Llama never ran. v1.3a fixed this same mismatch in ablation() ("restricted to the reps the ablation ran, so every comparison is on the same seeds"), but main() and run_contrasts() never apply it. It will also hit the confirmatory replication: 1 Llama repetition against 3 reference-agent repetitions. (where: harness/analyze.py:541-542 (main loads --ideal unfiltered), used by item_diffs 177-181 (did/faultfree), latex_macros 472-476 (Ideal macros), figure 422-425; triggered by notebooks/build_notebooks.py:271-272 (Llama cell passes the 2-rep runs_dev_ideal.jsonl)) 
  - fix: In main(), after loading: `if ideal is not None: ideal = ideal[ideal['rep'].isin(set(df['rep']))]`. This mirrors ablation(). Apply the same filter to confirm_ideal if power is ever computed for a 1-rep model.
- **[minor]** The protocol says the replication model's 9 contrasts are reported unadjusted. analyze.py Holm-adjusts every runs file, though, and the Llama-prefixed P and V macros carry the Holm p and the Holm-based verdict. No macro carries the raw p. The Llama Holm family also counts the 2 H1 integration rows, which are not estimable by design (p = 1). (where: harness/analyze.py:229-232 and 482-484; protocol/PROTOCOL.md:99-100) 
  - fix: Emit a raw-p macro (e.g. {name}Praw from r['p']). Or, when --prefix/--replication is set, base the V macro on the unadjusted p, as the protocol says. Also consider dropping not-estimable rows from the family for the replication.
